立派な実績はありません。ただ、この二つはやってきました。

芯にあること

月に一度の請求業務を、ほぼ一人で4年回した。止めたら会社のお金が止まる業務を、朝6時から翌2時までかかった月も含めて、48回、落とさずに回しました。

自社で受注したPOSレジを、現場が落ち着くまで通って収束させた。手探りで進め、エンジニアを雇い、サービスインさせました。運用開始直後のトラブルは、落ち着くまで2〜3か月、毎日現地に出向きました。納品で手を離さず、現場が回るまでいました。

普段やっていること

派手ではありません。誰かが放り出した、あるいは誰も引き受けたがらない部分を拾う仕事です。

  • 要件が固まらない案件に入り、「決まっていること／決まっていないこと」を整理する
  • 誰も全体を説明できない現場で、業務を言葉と図にする
  • 開発会社に見積を頼む前に、「何を頼めばいいか」を一緒に決める
  • 担当者が辞めたら回らない仕事を、回る形に書き起こす
  • 進行管理の手が足りない会社で、PM/PMOとして淡々と回す
  • 既存システムの保守・改修・仕様調査

エンジニア約20年、PM/PMO約7年。C# / VB.NET / Java / PHP / COBOL / MySQL / PostgreSQL ほか、業務システム全般。現在は複数の会社で、0.5〜0.8人月単位で並行稼働しています。

どういう人か

  • 会社員は向いていません。責任と権限がズレた場所、意味のない手順、誰も決めない現場が耐えられない。そのぶん、外からそれを指摘し、直す側に回っています。
  • 仕事では短く結論だけ言います。表面はやわらかいですが、言葉はきつくなることがあります。
  • 考えるときは図を描きます。会議のメモも図です。
  • 定例・会員制のコミュニティは苦手です。効いているのは、信頼できる一人からの個別紹介です。

こんな会社・人がいたら

  • システム化したいが、何を頼めばいいかわからない
  • 担当者が辞めたら業務が回らない、属人化している
  • 開発会社の見積が妥当かわからない
  • 案件は取れるが、回す人がいない
  • 社長として相談できる相手がいない
